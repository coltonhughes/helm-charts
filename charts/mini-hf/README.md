# Mini-HF

Mini-HF runs a browser UI, management API, Hugging Face API, ModelScope API,
two worker pools, and an Alembic migration Job. PostgreSQL is provisioned by
CloudNativePG and cache is provisioned by the official Valkey operator.

## Prerequisites

- CloudNativePG operator and `postgresql.cnpg.io/v1` CRD.
- [Official Valkey operator](https://github.com/valkey-io/valkey-operator) and
  its `valkey.io/v1alpha1` `ValkeyCluster` CRD.
- A Gateway API implementation and `gateway.networking.k8s.io/v1` HTTPRoute CRD
  if exposing any component through a route.
- A reachable S3-compatible service and a bucket created in advance. The chart
  does not install S3 storage.

The official Valkey operator creates Valkey in cluster mode. Mini-HF must use
a cluster-aware Valkey client. The chart points `REDIS_URL` at the cluster's
initial service seed; the client must follow cluster redirects.

## Configure

Set both image tags to versions published by your GitHub Actions workflows.
Set `s3.endpoint`, `s3.bucket`, `s3.accessKey`, and `s3.secretKey`; access and
secret keys are stored in a Kubernetes Secret. S3 credentials are deliberately
not generated by the chart. Until these settings are supplied, the chart still
renders but Mini-HF cannot use model storage.

The chart generates the JWT signing key, initial admin password, and CNPG
password when their corresponding values are empty. It reads the existing
Secret during upgrades to retain generated values. Set
`security.jwtSecretKey`, `admin.password`, or
`database.cnpg.credentials.password` to provide your own values. Changing an
explicitly supplied credential requires coordinating the value with the
existing database/application state.

Set `publicURLs.management`, `publicURLs.hf`, and `publicURLs.modelscope` to
the externally reachable URLs. These are used by the frontend and API servers
when they return public links. The defaults point to localhost for local
development.

The four HTTPRoutes are configured independently under `routes.ui`,
`routes.management`, `routes.hf`, and `routes.modelscope`. Each enabled route
requires `parentRefs` and should have a `hostnames` entry. Set the public URL
values to match the corresponding route hostnames and listener scheme.

## Install example

```yaml
image:
  backend:
    tag: "1.2.3"
  frontend:
    tag: "1.2.3"
s3:
  endpoint: https://s3.example.com
  bucket: mini-hf
  accessKey: replace-me
  secretKey: replace-me
publicURLs:
  management: https://api.example.com/api/v1
  hf: https://hf.example.com
  modelscope: https://ms.example.com
routes:
  ui:
    enabled: true
    parentRefs:
      - name: public-gateway
        namespace: gateway-system
    hostnames: [mini-hf.example.com]
  management:
    enabled: true
    parentRefs:
      - name: public-gateway
        namespace: gateway-system
    hostnames: [api.example.com]
  hf:
    enabled: true
    parentRefs:
      - name: public-gateway
        namespace: gateway-system
    hostnames: [hf.example.com]
  modelscope:
    enabled: true
    parentRefs:
      - name: public-gateway
        namespace: gateway-system
    hostnames: [ms.example.com]
```

```sh
helm install mini-hf ./charts/mini-hf -n mini-hf --create-namespace -f values.yaml
```

When installing with Flux, set `spec.install.disableWait: true` on the
`HelmRelease`. The chart's post-install migration Job must run before the
backend Deployments are ready; backend pods wait for the Alembic version row
before starting their application containers.

Management-server and worker scratch files use per-pod `emptyDir` volumes by
default. Set each workload's `scratch.existingClaim` to mount a pre-created PVC,
or `scratch.sizeLimit` to cap an `emptyDir`. Use storage large enough for the
largest in-flight model repository.

`workers.general` handles all task sizes; `workers.small` applies the configured
`maxRepoStorageGB` limit, matching the two Compose worker pools. Both replica
counts are configurable.
